Agent UI — konseptler

Bölüm 1 — 🤖 butonuna dokununca (A/B/C): agent paneli nereye gelir. Hepsi Claude Code tarzı tool satırları (kapalı özet → tap ile açılır), agent'ın kendi izole PTY'si, work mode yok.
Bölüm 2 — agent chat'ler nasıl yönetilir (D/E/F): liste nereden açılır, yeni chat nasıl oluşturulur, terminal session'a bağlı olmak zorunda mı.
Her sayfada state'leri tek tek değiştirip elle gezebilirsin.

KONSEPT A

Peek Bar

Agent, terminalin altına dock edilmiş ince bir bar olarak gelir. Terminal tamamen görünür kalır — üstte komut çalışırken altta agent'a yazıyorsun. Chevron'a tap → agent tam ekrana açılır, terminal arkaya blur/dim olur.

  • Terminal bağlamı hiç kaybolmaz — Drosh'un tez budur
  • Tek dokunuşla "sadece yap, göster" ayrımı
  • Serbest sürükleme yok → gesture çatışması yok
  • Telefonda bar dikey alan yiyor (~56dp + keybar)
  • Agent çalışırken bar'da sadece tek satır ticker

KONSEPT B

Draggable Sheet

Docs'taki "Model B". Standart Android bottom sheet — %58 yükseklikte, arkasında blur/dim'li terminal. Grabber'ı yukarı çek → tam ekran. İçerik alttan başlar, mesaj listesi yukarı kaydırılır.

  • Tanıdık Android paterni, öğrenme maliyeti sıfır
  • Sheet yüksekliği içeriğe göre ayarlanabilir
  • Sheet + LazyColumn iç içe → nested scroll çatışması
  • IME açılınca sheet yüksekliği + klavye yarışması
  • Back'de "sheet kapat mı, panel kapat mı" belirsiz

KONSEPT C

Agent = Bir Session

Agent özel bir panel değil, sıradan bir session. 🤖 butonu yeni bir Agent Session açar (izole PTY), session switcher'da 🤖 npm-fix olarak görünür. Ekranın üstünde Transcript / Terminal sekmesi — bir tıkla agent'ın canlı terminaline geçersin.

  • Session sistemiyle birebir aynı — yeni mental model yok
  • Agent'ın terminali birinci sınıf, transcript'ten bağımsız
  • Session kapatma/rename/switcher tümü zaten çalışıyor
  • Her görev için yeni session → session listesi şişer
  • "Bu Session'da çalış" kavramı geriye gelir

KONSEPT D

Global Drawer

Agent chat'ler mevcut SessionSidebar'a AGENT CHATS bölümü olarak ekleniyor. Aynı drawer hem terminal ekranında hem agent ekranında açılıyor. Satırda isim, çalışma dizini, son mesaj ve durum noktası. Uzun bas → rename / cwd değiştir / sil.

  • Tek yer — session'lar ve agent chat'leri aynı listede
  • Arama zaten var, sidebar zaten uygulanmış
  • Hiç yeni ekran / hiç yeni yüzey
  • Agent ekranındayken de drawer açmak "terminal kılıfı" gibi hissedebilir
  • İki tür liste aynı gözde → karmaşa

KONSEPT E

Agent Chat Switcher Sheet

Yönetim agent deneyiminin içinde: 🤖 butonu bir bottom sheet açar — chat listesi + arama + New agent chat. Sheet'in içinde çalışma dizini seçimi. Terminal sidebar'ı agent chat'lerinden habersiz kalıyor.

  • Bağlam doğru — agent ile uğraşırken agent yönetimi de yanında
  • Terminal yüzeyine hiç dokunmuyorsun
  • Bir agent chat'e girmeden listeye hiçbir yerden ulaşamazsın
  • Global giriş noktası yine gerekiyor

KONSEPT F

Agent Home

Agent chat'lerin kendi ana ekranı. Nereden açarsan aç 🤖 buraya gelir — anlamı net: "Agent'lar". Çalışanlar üstte gruplanır, kartta isim + son mesaj + dizin + süre. Boş durumda tek buton. FAB yeni chat'in çalışma dizinini seçtirir.

  • Paralel birden fazla görev varsa en doğru görünüm
  • Boş durum ve ilk kullanım düzgün tasarlanabilir
  • Yeni bir top-level ekran — ekran sayısı artıyor
  • "En son açılan chat'i doğrudan aç" kısayolu olmazsa iki dokunuş

Bölüm 2 — ortak karar: chat / session ilişkisi

Agent chat birinci sınıf

Agent chat kendi PTY'sini kendisi açar. Yani terminal session açmadan da agent chat oluşturulabilir — bu bir istisna değil, normal yol. "Bu session'da çalış" dediğin şey sadece başlangıç dizini ön-doldurulmuş bir seçenek.

İki tür, tek liste

Session ve agent chat aynı listede durur, ayrım yalnızca bir etiket (🤖). Ayrı bir tablo ya da ayrı bir arşiv mekanizması gerekmez — şişme sorunu zaten session tarafında mevcut.

PTY ömrü

Agent chat'in PTY'si yalnızca chat açıkken yaşar. Chat'ten çıkınca PTY kapanır, transcript kalır. Geri gelince yeniden açılır — aynı anda en çok 1 agent PTY.

Ortak kararlar (3 konseptte de aynı)

Tool satırları — Claude Code tarzı

Varsayılan kapalı: tek satır — ikon, tool adı, özet, süre. Tap ile açılır, altında tam çıktı / diff. Uzun shell çıktısı transcript'i boğmaz.

Shell çıktısı canlı akar

TerminalManager.executeCommand(..., onOutput) zaten streaming veriyor. Araç satırı açıkken satır satır düşer. 30 sn'lık apt install donmuş gibi görünmez.

Yazma = onay kartı

write_file unified diff gösterir, Uygula / Reddet. Onaylanana kadar dosyaya dokunulmaz. Reddedilirse agent'a CANCELLED döner, loop devam eder.

API key artık chat içinde değil

Provider + key + model ayarları bir sheet'e taşınır, EncryptedSharedPreferences'a yazılır (SecurityModule.kt pattern'ı). Bugün key her app açılışında kayboluyor.

Arka plan göstergesi

Agent panel kapandıysa çalışmaya devam eder; 🤖 ikonunda spinner + badge. Tıklayınca transcript'i bulduğun yerden açılır.

Sıkıştırılmış tool çıktısı

Her tool sonucu context'e kapsamlı gider. 300 satırlık cat tek pencereyi patlatır. Satır + karakter hard cap, uzunsa baş/son korunur.
